# 跑步一生

个人无限期 30 分钟跑步挑战，适配手机的静态 PWA。休息不清零，不要求连续打卡。

在线使用：[跑步一生](https://6eanut.github.io/run-for-life/)。在 iPhone Safari 打开后，可以通过分享菜单添加到主屏幕。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm ci
npm run dev
```

打开终端显示的网址。生产构建：

```sh
npm run build
npm run preview
```

## 使用

页面只保留“统计”和“数据导入”两个导航入口。页面顶部的发布信息下方始终显示终身累计跑步次数、公里数和运动时间，覆盖全部记录，不随时间筛选改变。不足 30 分钟的训练仍计入跑步记录和里程。

统计页新增时间范围工具栏“这一段时间的你”，内置“统计时间范围”选择：全部记录、近30天、近90天、今年或自定义。预设选中即刻生效；自定义需要填写“开始日期”“结束日期”后点击“应用时间范围”。日期无效或开始晚于结束时会显示友好提示，并保留上一个已应用的范围，不会覆盖或崩溃。工具栏下方明确显示当前应用的起止日期和记录条数。

“期间汇总”用一条精致的数字信息条展示选定范围内的 6 项指标：跑步次数、活跃天数、已记录公里、运动时间、动态千卡、累计爬升。数字明确属于所选期间，与顶部终身累计相互独立。缺少数据的指标显示“—”；部分记录没有距离时，会注明“X 次距离未记录，合计已知数据”，绝不把未知距离当成 0。范围内没有记录时给出空态提示。

“期间汇总”下方默认折叠着“跑步回顾与个人纪录”入口，展开后回顾所选范围内最近的一次训练：日期、地点、设备、强度，距离、时长、平均配速、平均心率，以及气温、湿度、空气质量等按记录原样呈现的气象数据；未知字段显示“—”。继续展开“更多指标与分段”可查看其余指标与逐公里分段配速（条形越长表示这一公里越慢，末段不足 1 公里不折算）。下方“这段时间的个人纪录”给出范围内最长距离、最长时长、最快平均配速与最高爬升及其日期，只与过去的自己比较。其中最快平均配速只比较满 30 分钟（1800 秒）的训练，短程冲刺不会占据该项。回顾条数不多时可下拉切换要回顾的某一次训练。选中训练后点击“生成纪念卡”，在本机生成竖版 PNG 预览；可勾选是否在卡片上显示地点（没有真实地点时不可勾选），确认后点击“保存 PNG”下载。识别进行中时该按钮暂不可用。

“十二周的脚步”是一张周一至周日、按周从旧到新排列的 12 周日历（7 行 × 12 列）。格子颜色按当天跑步次数加深；空格只是没有记录，不代表休息日，也不讲连续打卡、不生成假数据。日历以当前应用范围的结束日期（未应用时为今天）为锚点，自定义区间同样可以回看更早的 12 周。点击格子（或在手机、键盘上用“选择日期”下拉）即可查看该日详情：日期、次数、公里、运动时间，以及当天每次训练的开始时间、距离和时长，支持一天多次。未来日期不可选，也不当作休息日；落在当前范围之外的格子用弱化的斜纹表示，不冒充“未跑”。默认选中最近有记录的一天。文案“按已导入的记录展示，空格不代表必须跑”始终可见。

趋势与月度汇总同样只统计当前选定范围：距离、平均配速、平均心率、运动时长、步频和功率，按训练当地日期与开始时间排序。横轴反映真实日期间距；缺失指标留空并中断连线。可以逐次查看数值，或展开图表数据表。月度汇总显示范围内最多 12 个月的跑步次数与已记录里程。

1. 在“数据导入”选择同一场 Apple Fitness 训练的两张 PNG/JPG/WebP 截图，每张不超过 15 MB。
2. 核对截图气温单位（默认摄氏 °C；不确定可以选择留空）及训练时区（默认 Asia/Shanghai，可修改或清空）。点击识别，检查合并后的字段和分段。识别不到的字段保留空值；冲突需核对，可以展开“查看识别文字”检查。
3. 修改日期、时长、距离等字段，确认保存后才会计入档案。运动时长达到 1800 秒即完成一次挑战。
4. 保存后回到“统计”查看更新的累计和趋势。在“数据导入”下方查看、修改或删除记录，展开“备份与使用说明”可导入或导出 JSON 备份。

在“备份与使用说明 → 表格分析”导出本机全部训练指标或分段CSV，可用Excel或Numbers打开。CSV用于表格分析，恢复记录请保留JSON备份。

演示数据只打开待确认表单，不自动保存。识别支持双列指标、跨行标签、常见单位字形误读，并根据文字位置提取天气指标，避免将图标误读的数字直接计入温湿度或空气质量。

总距离会核对明细标签和跑步标题相邻的公里摘要；明细单位损坏时仍可使用唯一明确的摘要值，互相冲突的值保留为空。无法辨认的配速不会根据其他数据猜填。

首轮配速缺失时，会根据“平均配速”标签和行列间距定位原图区域，使用单行模式重新识别。区域参数只对该次识别生效，后续整图识别会重置参数。无可靠结果或区域读数互相冲突时保持空值。

强度卡片支持“耗能 二”等装饰符被误读的格式；等级或描述缺失时会补读原图卡片，同时读取等级和明确的描述，不根据等级推算描述。

页面顶部显示应用版本，手机上无需滚动即可查看。有新版本时点击“更新并刷新”，已保存的记录会保留；识别、编辑或导入期间暂不可更新。联网打开时优先加载最新页面，离线时使用已缓存的页面。

## 数据与识别

- Tesseract.js 中英文识别在浏览器本机执行。worker、WASM 和语言包从本应用同源地址加载，不发送截图至 OCR API。模型由锁定的 npm 依赖在构建时复制。
- 首次识别需要联网加载资源；成功使用后由 Service Worker / IndexedDB 缓存。缓存被清理或浏览器限制存储时，可能需要重新联网。离线运行需要先打开生产构建完成缓存。
- 图片仅在识别过程中存在内存，不保留原图；确认后的结构化记录保存在当前浏览器的 localStorage。没有账号和跨设备自动同步，清理网站数据会删除本机档案。请保存 JSON 备份至“文件”或其他可靠位置。
- 明确显示的运动时长优先，不以分钟精度的起止时间相减。分段不假定每段都是一公里，不从末段配速推导精确距离。心率曲线刻度不作为最大心率。
- 时区以截图明确值为先；未注明时使用用户设置的训练时区，并在表单提示核对。默认 Asia/Shanghai 已获用户确认，未来训练可修改。截图时区互相冲突时不覆盖。日期按训练当地显示值保存。
- 去重使用日期、运动类型、起始时间、时长和距离。信息不完整的相似记录要求确认；同一天的不同起始时间可分别保存。JSON 导入重算挑战状态，不信任备份自带计数。
- OCR 会受截图清晰度、语言、布局影响；保存前必须核对。当前以中文和英文标签为主，不承诺对所有语言和健身版本均准确。

## 部署到 GitHub Pages

1. 将本项目推送到自己的 GitHub 仓库，主分支为 `main`。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送后运行 `.github/workflows/pages.yml`：安装依赖、运行覆盖率检查、构建并发布 `dist/`。
4. 使用部署成功后显示的 HTTPS 地址，在 iPhone Safari 分享菜单选择“添加到主屏幕”。

默认使用相对资源路径，支持 `https://用户名.github.io/仓库名/` 子路径。不需要服务器、API 密钥或自定义域名。公开仓库只放程序和演示样例，请勿提交自己的备份或真实截图。

## 验证

```sh
npm test
npm run test:coverage
npx playwright install chromium webkit
npm run test:e2e
npm run test:pwa
```

如需在自己的机器上验收真实截图，将同次训练的两张 PNG 原图放入 `pic/` 后运行：

```sh
npm run test:local-images -- --project=chromium --project=chromium-mobile
```

此验收使用样例训练的预期数值，换用其他训练截图时应修改本地预期。`pic/` 和测试运行产物已忽略，不会提交原图，也不会在 GitHub Actions 中运行私有图片验收。

原图验收会检查所有表单输入及保存后的完整训练记录，逐项核对 5 个分段；另一用例故意破坏首轮配速和强度文字，再确认程序确实从原图区域恢复指标，避免只验证理想的整图 OCR 输出。

覆盖率门槛对解析、校验、合并、去重、趋势计算、备份存储和 OCR 模块设为 80%。验证包括单元/集成测试、Chromium 桌面及手机模拟的两个板块、趋势交互和数据管理流程、真实截图导入，以及生产构建的子路径与离线打开。真实截图验收确认了本次提供的两张图片；不同截图仍应核对结果。手机模拟使用 Chromium，不能视为 Safari 真机验证。

`e2e/mapping.spec.ts` 用手机端同类 OCR 文本模拟引擎输出，直接验证数字进入表单及无法辨认的配速留空。该测试覆盖文字到表单的映射，不代表图片 OCR 准确率。PWA 测试另验证确认更新后保留已保存记录。
