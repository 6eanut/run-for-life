# 跑步一生

个人无限期 30 分钟跑步挑战，适配手机的静态 PWA。休息不清零，不要求连续打卡。

在线使用：[跑步一生](https://6eanut.github.io/run-for-life/)。在 iPhone Safari 打开后，可以通过分享菜单添加到主屏幕。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm ci
npm run dev
```

打开终端显示的网址。生产构建：

```sh
npm run build
npm run preview
```

## 使用

1. 选择同一场 Apple Fitness 训练的两张 PNG/JPG/WebP 截图，每张不超过 15 MB。
2. 点击识别，检查合并后的字段和分段。识别不到的字段保留空值；冲突需核对。
3. 修改日期、时长、距离等字段，确认保存后才会计入档案。运动时长达到 1800 秒即完成一次挑战。
4. 在历史记录中查看、修改或删除训练。定期导出 JSON 备份，换手机时先预览再确认导入。

演示数据只打开待确认表单，不自动保存。没有实际截图时，测试里的文本是用户提供的人工转录，不能作为真实图片 OCR 准确率的证明。

## 数据与识别

- Tesseract.js 中英文识别在浏览器本机执行。worker、WASM 和语言包从本应用同源地址加载，不发送截图至 OCR API。模型由锁定的 npm 依赖在构建时复制。
- 首次识别需要联网加载资源；成功使用后由 Service Worker / IndexedDB 缓存。缓存被清理或浏览器限制存储时，可能需要重新联网。离线运行需要先打开生产构建完成缓存。
- 图片仅在识别过程中存在内存，不保留原图；确认后的结构化记录保存在当前浏览器的 localStorage。没有账号和跨设备自动同步，清理网站数据会删除本机档案。请保存 JSON 备份至“文件”或其他可靠位置。
- 明确显示的运动时长优先，不以分钟精度的起止时间相减。分段不假定每段都是一公里，不从末段配速推导精确距离。心率曲线刻度不作为最大心率。
- 时区是可编辑信息，不因地点北京自动填写；未识别到则为空。按训练当地显示的日期保存。
- 去重使用日期、运动类型、起始时间、时长和距离。信息不完整的相似记录要求确认；同一天的不同起始时间可分别保存。JSON 导入重算挑战状态，不信任备份自带计数。
- OCR 会受截图清晰度、语言、布局影响；保存前必须核对。当前以中文和英文标签为主，不承诺对所有语言和健身版本均准确。

## 部署到 GitHub Pages

1. 将本项目推送到自己的 GitHub 仓库，主分支为 `main`。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送后运行 `.github/workflows/pages.yml`：安装依赖、运行覆盖率检查、构建并发布 `dist/`。
4. 使用部署成功后显示的 HTTPS 地址，在 iPhone Safari 分享菜单选择“添加到主屏幕”。

默认使用相对资源路径，支持 `https://用户名.github.io/仓库名/` 子路径。不需要服务器、API 密钥或自定义域名。公开仓库只放程序和演示样例，请勿提交自己的备份或真实截图。
